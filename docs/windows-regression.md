# Windows 一键回归与构建追溯

在仓库根目录运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File windows\tests\Run-All.ps1
```

默认独立构建到 `windows/build/regression-<时间>-<随机标识>/bin`。测试通过 Windows PowerShell 5.1 的 STA 进程运行，使用合成配置、短信和 IMAP 响应，不连接真实邮箱、不启动已安装的程序。

已有构建可使用 `-ExePath <codepass.exe>`；旁边必须有对应的 `build-info.json`，EXE 哈希、版本戳与当前源码摘要必须匹配。没有构建元数据或来自旧源码的 EXE 会被拒绝。若明确需要测试另一个源码版本，可加 `-AllowDifferentSource`，该模式只验证指定构建，不证明当前源码的交付状态。

## 产物与失败处理

每次运行保留 `build.log`、各测试的 `.log`、可用的 `evidence/` 截图、EXE/构建元数据和 `summary.json`。截图只写入本次运行目录，不改指定 EXE 旁的已有图片。汇总包含各套件通过/失败数、退出码、截图不可用数量、总计、构建标识与 EXE 哈希。任一构建、元数据、功能/几何测试或差异检查失败都会返回非零退出码。桌面锁定等环境下，新增套件不会保存空白图，而是输出 `EVIDENCE_UNAVAILABLE` 并记录 `evidenceUnavailable`；功能与几何检查通过不代表视觉检查已完成，发布前应在解锁桌面复测画面。

回归结束时只把本次运行创建的合成数据目录移入 Windows 回收站，拒绝处理目录链接。EXE、测试日志与汇总保留供核对。不要把真实配置或历史文件复制进合成目录。

## 版本来源

产品版本来源为 `windows/src/Updater.cs` 的 `AppVersion`，当前 Windows v1.0.4；手机模块保持兼容的 v1.0.3。构建脚本核对中英文 README、CHANGELOG 与发布说明，不一致时拒绝构建。

每次构建包含产品/程序集版本、UTC 时间、Git 提交与工作区状态、源码摘要，并生成 `build-info.json` 和 EXE SHA-256。工作区未提交时构建标识包含 `dirty`，不表示已发布。源码摘要和 EXE 哈希用于区分同版本的不同本地构建。

隔离构建示例：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File windows\build.ps1 -OutputDirectory windows\build\local-check -SkipPackage
```

`-SkipPackage` 只生成本地构建，不更新发布 ZIP。正常打包使用显式白名单，包含 EXE 与构建元数据，不带本机配置、历史或日志。

## 记录、诊断与布局

记录页默认全部，可组合短信 / 邮件筛选与搜索，查询发件人、验证码、时间和已保存原文；多个词以空白分隔且全部匹配。不保存搜索词，仅搜索当前最多 100 条记录。

关于页提供「预览脱敏诊断」。报告只含白名单字段和归类事件，不读原始日志；先预览再保存完全相同的文本，不自动上传。不收录账号、地址、路径、主题、规则文本、正文、验证码或凭据；不会覆盖运行配置、历史和日志。

邮箱实时状态置顶，连接 / 规则 / 高级设置独立分卡；短信接收、连接与处理、ntfy、过滤和配置管理分卡。设置内容区小于 850 时标签置于输入上方，放宽后恢复原位置；按钮按可用宽度换行，窗口最小宽度 780。`evidence/` 中保留合成记录和宽窄窗口截图。
