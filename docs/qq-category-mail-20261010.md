# QQ 分类文件夹漏收修复

## 真实原因

已通过用户当前账号的只读 IMAP 查询确认：新发送的 Microsoft 安全代码邮件进入 QQ 的分类文件夹，而不是 INBOX 或垃圾箱。该邮件的主题命中当前关键词，正文有明确验证码上下文，现有提取器可以成功提取。

旧版仅监测 INBOX 和可选垃圾箱，没有检查这个分类目录，因此 QQ 提醒闪动但 codepass 没有收录。收件箱最新的另一封普通 Microsoft 通知不命中规则，不能把其中普通数字当作验证码。

检查没有输出授权码、验证码、主题或正文；没有改变用户配置、水位、历史或邮件已读状态。

## 修复

- 收件箱继续使用 IDLE；辅助线程检查分类/自定义收件目录，按配置的 10～600 秒间隔轮询。
- QQ 新邮件提醒同时唤醒收件箱与分类目录。
- 分类目录不依赖“检查垃圾箱”开关；该开关仍只控制垃圾/广告目录。
- 排除 Sent/Drafts/Trash/All 特殊用途目录，以及已发送、草稿、已删除等名称及其子目录。
- 目录排除使用服务器 LIST 返回的真实层级分隔符，并继承特殊目录根的排除属性，覆盖点号层级和自定义删除目录的子目录。
- 每目录使用独立身份+UIDVALIDITY 水位；新发现的分类目录先补查近 30 分钟，再保存初始水位，读取失败可重试。
- 首次补查仅处理 EXAMINE 时已有的 UID，之后到达的邮件走正常新邮件路径；水位表不再静默限制 64 个目录，避免活动目录和 INBOX 水位被淘汰。
- 首次补查只增加历史，不自动复制，也不改变“最新验证码”；之后新邮件按现有设置通知和复制。

## 使用

退出当前 codepass，使用新版 EXE 启动并保留原配置。若目标邮件仍在近 30 分钟内，首次检查分类目录会补收录；也可点击“重新检查近 30 分钟”。超过时限则重新触发一封验证码邮件。

构建：`windows/dist/qq-category-mail-20261010/codepass.exe`。版本仍为 v1.0.3，未发布。
